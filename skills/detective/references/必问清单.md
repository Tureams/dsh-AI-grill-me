# 必问清单 · 九格细化

> 用法：这不是一份要照着从头念的问卷，而是一份**问题库**。每轮挑当前最关键的一格问，
> 先给出你的假设，再让用户纠正。用户已经说清楚的格子不要重复问。

## 1. 目标
- 你想解决的是谁的什么问题？现在没有它的时候，你是怎么凑合的？
- 做完之后，哪一件以前做不到的事变得能做了？
- 有没有时间／预算／体量上的边界？
- 这件事如果只做一半，你希望先保住哪一半？

## 2. 使用者
- 只有你自己用，还是别人也要用？几个人、什么水平？
- 有没有「给别的 AI 用」的场景（比如做成 Skill／插件给别人装）？
- 使用者需要先学什么吗？

## 3. 使用场景
- 你在什么时候会打开它？多久用一次？
- 在什么设备／环境里用（手机、电脑、离线、没网）？
- 现在这件事你通常怎么做？最烦的是哪一步？

## 4. 功能清单
- 必须有的（少一个就不可用）是哪几个？
- 有了更好、没有也能活的（可选）是哪几个？
- 有没有你明确**不想要**的功能？
- 这些功能里，哪几个是「第一版就要」、哪几个可以留到后面？

## 5. 交付物类型与格式（**不可跳过**）
逐类确认，每类都要问：**要几份、叫什么名字、放在哪个目录**。

| 类型 | 需要追问的点 |
|---|---|
| Markdown / 纯文本 | 单文件还是多文件；有没有固定章节结构 |
| 可编辑文档 | .docx / .pptx / .xlsx？模板样式、字体、页数 |
| 只读文档 | .pdf？手机平板能不能看 |
| 图片 | .svg 还是 .png；要不要可编辑的源文件；尺寸 |
| 代码 | 什么语言／框架；能不能直接跑；要不要示例数据 |
| 网页 / 应用 | 静态还是需要服务端；部署在哪 |
| 可执行程序 / 安装包 | 目标系统；怎么安装 |
| 数据 / 配置 | 格式（json/yaml/csv）；样例数据 |

必问句：
- 这份东西你是要**编辑**它，还是只要**看**它？
- 需要打印或投屏吗？
- 中文排版有要求吗（字体、简繁）？
- 交付时你希望我一次给全，还是分层给（先骨架再内容）？

## 6. 形态与技术栈
- 纯提示词／纯文档，还是要带脚本、带程序？
- 有偏好的语言、框架、库吗？有没有必须避开的东西？
- 有现成的模板或参考案例吗（有的话请你给我，我不自己去翻）？

## 7. 平台与分发
- 在哪个平台运行（本机 DSH、别人的 DSH、GitHub、网页、桌面端）？
- 要不要给别人装？别人装的时候你希望是几步？
- 要不要上包管理器（npm）？要不要版本号规则？
- 卸载要干净吗？

## 8. 验收标准（问到用户能说「满意」）
- 怎样才算你满意？请给一句能检验的话。
- 你会怎么验？（打开看一眼／跑一次／给别人用／看输出对不对）
- 什么情况算失败？最不能接受的错误是什么？
- 交付之后出 bug 怎么办：你希望我继续修，还是你自己改？
- 用户说不出验收标准时：给两三个候选让他挑，不要替他定，也不要跳过这一格。

## 9. 命名与目录
- 项目／包／模式／文件分别叫什么？
- 名字有什么禁忌（不能和别人撞、必须是英文、必须有中文）？
- 目录结构你有偏好吗？中文目录名可以接受吗？
- 许可证／版权署名怎么写？

## 常用追问句（卡住时用）

- 「我现在的理解是 X（置信度 Y）。如果错了，是错在哪一层？」
- 「这件事你有没有想过相反的方案？为什么不要它？」
- 「如果只能保留一个功能，你砍哪个？」
- 「这个决定的代价你接受吗：例如 A 更简单但 B 更灵活。」
- 「你说的『快』『简单』『好用』，具体到什么程度算达到？」

## 提问纪律（来自模式铁律）

1. 一轮问几个由自己自适应判断，不要九格齐发，也不要死板地一轮一问。
2. 选项里可以写推荐，但必须注明「推荐 ≠ 已确认」。
3. 用户没明确确认的，标「我的推理（未确认）」并保留，不替他决定。
4. 用户没有指出错误的项，不再反复追问。
5. 追问不设轮数上限，但**每满十轮必须强制产出初版交付**（一问一答算一轮）。
6. 同一格反复无共识 → 熔断，直接给草案让他改，不必等满十轮。
7. 交付后追问「满意吗」；用户说满意才算成功。
